# Flutter APK via GitHub Actions — CI pitfalls (verified 2026-08, DebDown+ project)

Flavor of `android-apk-ci-build` where the app is Flutter (not raw Gradle/Kotlin).
Same class of task: repo + workflow on a server, APK artifact comes back from CI.

## 1. Repo with NO Flutter scaffolding → "Unsupported Gradle project" / missing android/ dir
If the repo was hand-initialized (only pubspec.yaml, lib/, assets/), the android/
project doesn't exist, so `flutter build apk` fails. Fix: run `flutter create`
INSIDE the workflow BEFORE pub get / build:

```yaml
- name: Set up Flutter
  uses: subosito/flutter-action@v2
  with:
    flutter-version: '3.19.x'
    channel: 'stable'
    cache: true
- name: Initialize Flutter Project Scaffolding
  run: flutter create . --org com.debdownplus --project-name debdown_plus --platforms=android
- run: flutter pub get
- run: flutter build apk --release
- uses: actions/upload-artifact@v4
  with:
    name: DebDown-Plus-Release
    path: build/app/outputs/flutter-apk/app-release.apk
```

Caveat: `flutter create .` regenerates android/ scaffolding — it OVERWRITES
AndroidManifest.xml and deletes custom MainActivity.kt paths that don't match the
generated package. Keep custom android/ files at the exact paths flutter create
generates, or re-apply them after the create step.

## 2. Package name derivation (kills MainActivity/Manifest builds)
`flutter create --org <org> --project-name <name>` → applicationId / package =
`<org>.<name>` (e.g. `com.debdownplus.debdown_plus`). Consequences:
- MainActivity.kt MUST live at `android/app/src/main/kotlin/<pkg with / separators>/MainActivity.kt`
  (e.g. `com/debdownplus/debdown_plus/MainActivity.kt`) with `package com.debdownplus.debdown_plus;`
- `<application android:name="${applicationName}">` in the manifest is a Flutter
  template placeholder — fine as-is.
- Check the manifest package with `android:package="com.debdownplus.debdown_plus"`.

## 3. Android resource linking failure: `resource xml/file_provider_paths not found`
`<provider android:name="androidx.core.content.FileProvider" ...>` referencing
`@xml/file_provider_paths` fails `:app:processReleaseResources` if
`android/app/src/main/res/xml/file_provider_paths.xml` is missing. The res/xml
file is NOT generated by flutter create — always write it alongside any
FileProvider entry. Minimal contents:

```xml
<paths xmlns:android="http://schemas.android.com/apk/res/android">
  <files-path name="files" path="." />
  <cache-path name="cache" path="." />
  <external-path name="external" path="." />
  <external-files-path name="external_files" path="." />
  <external-cache-path name="external_cache" path="." />
</paths>
```

## 4. Receiving shares (YouTube/TikTok share sheet → app) 
In `android/app/src/main/AndroidManifest.xml`, on `.MainActivity` add:

```xml
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="text/plain" />
</intent-filter>
```
- Set `android:launchMode="singleTask"` (receive_sharing_intent README: prevents a
  new activity instance per share; plugin handles onNewIntent itself).
- `receive_sharing_intent` v1.9.0 self-registers via FlutterPlugin — you do NOT
  need a custom MainActivity for sharing. Custom MainActivity is only needed for
  your own MethodChannels.
- Dart side must listen to BOTH: `getMediaStream()` (app already open) and
  `getInitialMedia()` (app cold-started by share) + `reset()` after handling.
- **API gotcha v1.9.0**: `SharedMediaFile` has NO `.text` getter (compiles to
  "getter 'text' isn't defined"). Text shares arrive in `.path`.
- VERIFY the intent filter actually shipped: binary AndroidManifest.xml inside the
  APK stores strings as UTF-16LE:
  ```bash
  unzip -o -q app-release.apk AndroidManifest.xml -d /tmp/apk_check
  python3 -c "
  d = open('/tmp/apk_check/AndroidManifest.xml','rb').read()
  for s in ['android.intent.action.SEND', 'text/plain']:
      print(s, '->', 'FOUND' if s.encode('utf-16-le') in d else 'MISSING')
  "
  ```
  Plain utf-8 grep returns MISSING for everything — that's expected, not a bug.

## 5. Kotlin stdlib duplicate class conflict (share_plus)
Adding `share_plus` to a Flutter 3.19 template can fail
`:app:checkReleaseDuplicateClasses`:
`Duplicate class kotlin.collections.jdk8.CollectionsJDK8Kt ... kotlin-stdlib-1.8.22 ... kotlin-stdlib-jdk8-1.7.10`.
Fix that works: drop share_plus; hand-roll share via MethodChannel + FileProvider
(no extra transitive deps):
- Kotlin: `MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.x/share")`
  with `"shareFile"` method → `FileProvider.getUriForFile(this, "$packageName.fileprovider", file)`
  → `Intent(ACTION_SEND)` with `EXTRA_STREAM`, `FLAG_GRANT_READ_URI_PERMISSION` → chooser.
- Dart: `MethodChannel('com.x/share').invokeMethod('shareFile', {'path': ..., 'text': ...})`.

## 6. youtube_explode_dart API quirks (compile-time getters)
- MP4 with sound: use `manifest.muxed.withHighestBitrate()` — `videoOnly` streams
  are video WITHOUT audio (user: "YT sukses tapi ga ada suara").
- `VideoQuality` in the RESOLVED version (^2.2.4): `.qualityString` COMPILES but
  throws at RUNTIME `NoSuchMethodError: Class 'VideoQuality' has no instance
  getter 'qualityString'` (seen on device logs — it's an extension getter whose
  presence varies by resolved version; master has it, 2.2.4's lockfile does not).
  `.label` does not exist at all (compile error). **Safe cross-version choice:
  `.name`** (built-in Dart enum getter, always present).
- `AudioOnlyStreamInfo` exposes `audioCodec` (String), NOT `audioQuality`.
- Platform gate before downloading: youtube_explode_dart is YouTube-only; feeding
  a TikTok/IG URL throws "Invalid argument (idOrUrl)". Check `uri.host` against
  youtube.com / youtu.be / youtube-nocookie.com (or 11-char bare ID) and show an
  honest "unsupported platform" message instead of the raw error.
- Transient `SocketException: Failed host lookup` on Android → retry loop
  (3 attempts, ~2s delay) around `videos.get` + `getManifest`; catch
  `SocketException` separately for a clean "[NETWORK ERROR]" message.
- **Ceiling**: youtube_explode_dart is YouTube-only. When the requirement is
  TikTok/IG/X/1000+ sites + playlists + MP3, swap the engine for bundled
  yt-dlp — see `ytdl-android-embed.md` in this skill (deps, minSdk 24,
  MethodChannel/EventChannel bridge, build.gradle injection).

## 7. CI error triage loop (used repeatedly, works)
```bash
gh run list --repo owner/repo --limit 3
gh run watch <id> --repo owner/repo --exit-status   # exit-status => non-zero on failure
gh run view <id> --repo owner/repo --log-failed 2>/dev/null | grep -iE "error:|Exception|What went wrong"
```
The `flutter build apk` step logs "Running Gradle task 'assembleRelease'" then
the Dart compile errors appear as `lib/main.dart:<line>:<col>: Error: ...` —
those are Flutter compile errors, fix in Dart; anything under `* What went wrong:`
is Gradle/Android config, fix in android/ or pubspec.

## 9. Shrinking the APK: `--split-per-abi` (native-engine apps make FAT APKs)
Bundled native engines (youtubedl-android = Python + yt-dlp + ffmpeg for 3 ABIs)
blow a fat APK to ~170 MB. `flutter build apk --release --split-per-abi` emits
one APK per ABI — arm64-v8a lands ~58 MB (all modern phones), armeabi-v7a
~52 MB, x86_64 ~61 MB. Functionality is unchanged; each APK just carries one
ABI. Upload all three to the release; rename the arm64 one to the app name so it
becomes the obvious "main" download link.
- **Conflict pitfall**: an `ndk { abiFilters [...] }` block in app/build.gradle
  (common when adding a native lib) makes the build FAIL once split-per-abi is on:
  `Conflicting configuration : 'armeabi-v7a,arm64-v8a,x86_64' in ndk abiFilters
  cannot be present when splits abi filters are set`. Remove the abiFilters
  block (keep the minSdk bump) — split-per-abi already restricts ABIs per
  artifact, so the block is redundant AND fatal.
- Artifact names after split: `build/app/outputs/flutter-apk/app-<abi>-release.apk`.
- Release upload pattern (rename for clarity, `||`-fallback to upload --clobber
  so re-runs don't fail on an existing tag):
  ```bash
  cd build/app/outputs/flutter-apk
  cp app-arm64-v8a-release.apk DebDownPlus.apk      # main link
  gh release create "$TAG" DebDownPlus.apk app-arm64-v8a-release.apk \
      app-armeabi-v7a-release.apk app-x86_64-release.apk \
      --repo "$GITHUB_REPOSITORY" --title "..." --notes "..." || \
  gh release upload "$TAG" DebDownPlus.apk app-arm64-v8a-release.apk \
      app-armeabi-v7a-release.apk app-x86_64-release.apk \
      --repo "$GITHUB_REPOSITORY" --clobber
  ```
- Verify what actually shipped:
  `gh api repos/<owner>/<repo>/releases/tags/<tag> --jq '.assets[] | "\(.name) | \(.size/1048576 | floor) MB | \(.browser_download_url)"'`
  (APK sizes confirm the split worked: 3 assets, ~50-60 MB each, NOT one 170 MB).

## 10. Maven Central HTTP 429 during Gradle resolution — rerun, don't fix
`Could not resolve com.squareup:javawriter:2.5.0 ... Received status code 429
from server: Too Many Requests` (also `org.ow2.asm:asm:9.1`) inside
`* What went wrong:` is a TRANSIENT rate limit on repo.maven.apache.org —
NOT a code/config bug. Fix: `gh run rerun <run-id> --repo owner/repo` (or
re-push). It usually passes on the retry; don't touch the build config.

## 11. Verifying bracket balance in edited Dart/Kotlin source
After large multi-patch edits, `s.count('{') == s.count('}')` naive checks
false-positive on `[`/`]` inside regex/string literals (e.g. a Dart regex
`r'[^\]]*'`). Use `scripts/check_brackets.py` from this skill instead — it
strips strings/comments first, then counts. Curly/paren/square all balanced
in code = structure is sound; then grep for the symbols you referenced to
confirm definitions exist.
- Static TTF weights are NOT in the googlefonts/saira repo (404s). Use the
  variable font from google/fonts:
  `https://raw.githubusercontent.com/google/fonts/main/ofl/saira/Saira%5Bwdth%2Cwght%5D.ttf`
  (URL-encode the `[` `]` brackets!). Validate with magic bytes
  `00 01 00 00` (or `true`/`OTTO`) before committing.
- Register the SAME variable TTF once per weight in pubspec so `FontWeight.w900`
  etc. resolve:
  ```yaml
  fonts:
    - family: Saira
      fonts:
        - asset: assets/fonts/Saira-Variable.ttf
          weight: 300
        # ...repeat for 400/500/600/700/900
  ```
- Then `fontFamily: 'Saira'` in ThemeData is the single switch for the whole UI.

## 12. Dart compile errors that bite AFTER big UI patches (seen on DebDown+ v1.3.2)
These surface in the CI log as `lib/main.dart:<line>:<col>: Error: ...` right
after "Running Gradle task 'assembleRelease'" — fix in Dart, no Gradle changes:
- **MethodChannel results are nullable**: `final dir = await _ytdl.invokeMethod<String>('defaultDir')`
  gives `String?`; assigning to a `String` field fails with
  "A value of type 'String?' can't be assigned to a variable of type 'String'".
  Use a fallback: `_lastSavedPath = dir ?? _lastSavedPath;` (or `!` when the
  contract guarantees non-null).
- **Dart record literal field style MUST match the target type annotation**:
  a list declared `(icon: ..., color: ..., label: ...)` (NAMED fields) is type
  `({IconData icon, Color color, String label})`, which is NOT assignable to a
  parameter typed `(IconData, Color, String)` (positional):
  "The argument type '({Color color, IconData icon, String label})' can't be
  assigned to the parameter type '(IconData, Color, String)'."
  Keep both sides the same style — either both named or both positional.
- After fixing, verify bracket balance with `scripts/check_brackets.py` before
  pushing again (cheap insurance against a second failed build cycle).

## 13. Release tag comes from pubspec version — bump BEFORE pushing
The release step derives the tag from pubspec: `TAG="v$(grep '^version:' pubspec.yaml | awk '{print $2}' | cut -d'+' -f1)"`.
- If you add features but FORGET to bump `version:` in pubspec.yaml, the build
  succeeds but no new release appears: the `|| gh release upload ... --clobber`
  fallback silently OVERWRITES the previous release's APK assets instead.
  First symptom: `gh api .../releases/tags/<new-tag>` → 404, and the release
  list still shows the old version.
- Rule: bump `version: X.Y.Z+1` in pubspec AND the in-app version strings
  (SYSTEM READY line, startup log, log-file header — sed across lib/) in the
  same commit as the feature work. After a successful build, verify the tag
  exists: `gh api repos/<owner>/<repo>/releases/tags/<tag> --jq '.tag_name'`
  (a 404 means the version bump was missed).

## 14. Proper APK signing in CI (Flutter)
To avoid Play Protect "App not recognized" warnings, sign release APKs with a
proper keystore in CI using `r0adkll/sign-android-release@v1`.

### Keystore generation (one-time)
```bash
keytool -genkeypair -v -keystore myapp-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias myapp -storepass <STORE_PASS> -keypass <KEY_PASS> \
  -dname "CN=MyApp, OU=MyApp, O=MyOrg, L=City, ST=State, C=ID"
base64 -w 0 myapp-release.jks   # paste into SIGNING_KEY secret
```

### GitHub Secrets (4)
`SIGNING_KEY` (base64), `ALIAS`, `KEY_STORE_PASSWORD`, `KEY_PASSWORD`

### Workflow step
```yaml
- name: Set up Android SDK (for zipalign/apksigner)
  uses: android-actions/setup-android@v3
  with:
    api-level: 34
    build-tools-version: '29.0.3'  # <-- CRITICAL: sign action expects 29.0.3
    emulator: false

- name: Sign APKs
  uses: r0adkll/sign-android-release@v1
  with:
    releaseDirectory: build/app/outputs/flutter-apk
    signingKeyBase64: ${{ secrets.SIGNING_KEY }}
    alias: ${{ secrets.ALIAS }}
    keyStorePassword: ${{ secrets.KEY_STORE_PASSWORD }}
    keyPassword: ${{ secrets.KEY_PASSWORD }}
```

### Pitfall: build-tools version mismatch
`r0adkll/sign-android-release@v1` hardcodes search for
`/usr/local/lib/android/sdk/build-tools/29.0.3/zipalign`. If
`android-actions/setup-android@v3` installs a different version (30.0.3,
34.0.0), signing fails with "Couldnt find the Android build tools @ .../29.0.3".
**Always pin `build-tools-version: '29.0.3'`** in the setup-android step.

### Verify signing
```bash
unzip -p app-arm64-v8a-release.apk META-INF/CERT.RSA | keytool -printcert | grep -i "owner\|issuer"
# Should show your CN=MyApp, not "CN=Android Debug"
```
